# `Int64`: Godot's 64-bit integers in AS3

**Status:** approved by the owner on 2026-11-14, with the rule proposed in section 2. The three rulings in
section 9 are the builder's and stand until the owner changes them. Built in stage 2b-3, as a part of its
own.

## 1. Why

Godot's integer has 64 bits. AS3's `int` and `uint` have 32, and `Number` holds whole numbers exactly only
up to 2^53. Today a wide Godot integer is declared `Number`, from a table kept by hand. Measured in Godot
4.7.2:

| What | Godot's value | As a `Number` today |
|---|---|---|
| `RefCounted.new().get_instance_id()` | `-9223372010514545211` | Rounded: the id no longer names the object |
| `Color(1, 1, 1, 1).to_rgba64()` | `-1` | Right |
| `randi()` | up to 4,294,967,295 | Declared `uint` by the table |

The owner decided on 2026-11-12: a real `Int64` type, given by one rule with no table kept by hand,
converting to `int`, `uint` or `Number` with a range check and never silently.

## 2. Which Godot integers are `Int64`

**What was approved:** "a Godot integer that Godot's description marks as 64-bit is an `Int64`."

**What the description holds.** It marks a width only on the methods and properties of classes. It marks
none on the built-in types (`Color`, `Array`, the packed arrays), on global functions, or on signal
arguments:

| Where | Integers | Width in the description |
|---|---|---|
| Methods of classes (a property takes its accessor's width) | 5,482 marked: 688 of them 64-bit | Yes |
| Built-in types | 472 | No |
| Global functions | 44 | No |
| Signal arguments, and 2 method arguments | 127 | No |

Every entry of today's table is in the unmarked rows. So the approved rule, read by its letter, removes no
entry: what an unmarked integer becomes is the real decision.

**The rule (approved).** A Godot integer is an `Int64` unless the description says it is narrower. Two things
count as "says it is narrower":

1. A width mark below 64 bits, as today (`int32` is `int`, `uint32` is `uint`).
2. A built-in type that stores 32-bit integers keeps `int` for all its integers. The description gives
   this for `Vector2i`, `Vector3i` and `Vector4i` (their members are marked `int32`) and so for `Rect2i`,
   which is made of them. `PackedInt32Array` says it in its name; that one name is the only thing left
   that is written by hand, and a test checks it still exists. (`PackedByteArray` was first on this list
   and came off while building: it also reads and writes 64-bit integers, `decodeS64` and the like. A byte
   past 255 is cut by Godot, as in GDScript; that is in the backlog.)

Point 2 is needed because Godot cuts a wide value off inside these types without an error. Measured:
`Vector2i(5000000000, 0)` is `(705032704, 0)`, and `PackedInt32Array.append(5000000000)` stores
`705032704`. With `int` parameters the wide value never reaches Godot.

**What it changes for a script.** The declared type, and almost never the code:

```actionscript
// Before: size() is declared int.        After: size() is declared Int64.
var n:int = items.size();                 // The same line. It now checks that the size fits an int.
for (var i:int = 0; i < items.size(); i++) {}   // The same line.
var roll:int = randiRange(1, 6);          // The same line.
```

**The other choice:** keep the table. Then `size()` stays `int`, and every wide method Godot adds must be
found and added by hand; one that is missed raises an error when its value is wide.

**Decided:** the rule above. It is the only one with nothing to keep up to date.

## 3. The type

- `Int64` is a top-level class, like `int`. A variable of it is never null and starts at 0.
- It is signed. Godot has no unsigned 64-bit integer: a value it marks unsigned arrives with the same bits,
  and reads as GDScript shows it (an object id can be negative). Ids are only compared and passed back.
- `Int64.MAX_VALUE` and `Int64.MIN_VALUE`.
- Text: `trace(x)`, `"" + x` and `String(x)` give its digits. `x.toString(radix = 10)`.
- A whole-number literal written where an `Int64` is expected is taken digit by digit, so every value can
  be written: `var big:Int64 = 9223372036854775807;`. Anywhere else a literal is what it is today.

## 4. Conversions

One rule: **a conversion the script did not write checks; a conversion the script wrote is AS3's.**

| From | To | Not written (assignment, argument, return) | Written (`int(x)`, `Number(x)`) |
|---|---|---|---|
| `int`, `uint` | `Int64` | Always fits | The same |
| `Int64` | `int`, `uint` | `RangeError` if the value is outside the type | Keeps the low 32 bits, as `int(5e9)` does in AS3 |
| `Int64` | `Number` | `RangeError` if the `Number` would not hold the same value (past 2^53) | Rounds to the nearest `Number` |
| `Number` | `Int64` | Drops the fraction, as for `int`. `RangeError` for `NaN`, an infinity, or a value outside 64 bits | `NaN` and infinities give 0; a value outside is held at the nearest end |
| `String` | `Int64` | Not allowed, as for `int` | `Int64("123")` reads the digits |

## 5. Arithmetic

- `+`, `-`, `*`, `%`, the bitwise operators and the shifts, between an `Int64` and an `Int64`, `int` or
  `uint`: the result is an `Int64`. Past 64 bits it wraps, as Godot's does.
- `/` gives a `Number`, as it always does in AS3. Write `Int64(a / b)` for a whole result.
- With a `Number` on the other side the result is a `Number`, and the `Int64` side converts by the
  unwritten rule above: a value past 2^53 raises a `RangeError`.
- `%` by zero raises an `Error`: there is no `Int64` that means "not a number".
- Comparisons are exact, with any numeric type on the other side.
- `Int64` counts as a whole number in the rule for Godot's integer vectors: `cell * count` stays a
  `Vector2i`.

## 6. At Godot's edge

- An `Int64` parameter takes any Godot integer. An `int` or `uint` parameter keeps its range check.
- This holds for every way a value enters a script: a call from GDScript, a listener's arguments, a
  virtual method Godot calls (`_computeCost(fromId:Int64, toId:Int64)`), a value Godot gives back.
- An `Int64` field read from GDScript is a Godot integer.

## 7. Inside the compiler

- The checker gets one more numeric type; the IR one more kind of register (`I64`). A register already has
  64 bits.
- The generator's table of widths is deleted. Checked when it went: 1,059 declarations changed (739 from
  `Number`, 309 from `int`, 11 from `uint`), every one to `Int64`.
- A whole number written out beside an `Int64` (`w == 9223372036854775807`, `w + 5000000000`) is an
  `Int64` too, read digit by digit. Anywhere else it is a `Number`, as in Flash.
- A `Number` parameter takes one of Godot's integers only if the `Number` holds the very same value.
- Native code (stage 3) uses the machine's own 64-bit integer.

## 8. Not in this design

- `Vector.<Int64>` and an `Int64` in an `Array` or `Object` arrive with those types (stage 2c).
- An unsigned 64-bit type. Godot has none.

## 9. Rulings made while writing, for the owner to change

| Ruling | The other choice |
|---|---|
| `int(x)` on an `Int64` keeps the low 32 bits, as Flash does for a `Number`. It is the way to say "cut it off". | It checks too, and a second spelling does the cut. |
| `Int64` arithmetic wraps at 64 bits. | It raises a `RangeError`. |
| `Int64 / Int64` is a `Number`. | It is a whole `Int64`, as in GDScript. |
